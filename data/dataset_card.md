 Step-by-Step Normalization (`UNF → 1NF → 2NF → 3NF`)

 1. Entity Identification
Analyzing the 10 columns of `synthetic_telemetry_data-selected-columns.csv` (`vehicle_id`, `brand`, `timestamp`, `odometer_reading`, `engine_temp_c`, `engine_rpm`, `oil_pressure_psi`, `coolant_temp_c`, `fuel_level_percent`, `fuel_consumption_lph`) alongside the operational fleet domain yields 7 normalized entities (exceeding the 5-table minimum)[cite: 7]:
1. `VEHICLES` — Fleet vehicle master registry (`vehicle_id`, `brand`, `plate_number`, `current_odometer`, `operational_status`).
2. `TELEMATICS_DEVICES` — Physical OBD-II hardware installed in each vehicle (`device_id`, `vehicle_id`, `imei_serial`, `firmware_version`, `device_status`).
3. `DRIVERS` — Anonymized fleet operators assigned to vehicle dispatches (`driver_id`, `driver_code`, `license_category`, `safety_score`, `driver_status`).
4. `TRIPS` — Scheduled and active journeys (`trip_id`, `vehicle_id`, `driver_id`, `start_time`, `end_time`, `origin_zone`, `destination_zone`, `trip_status`) — resolves the many-to-many relationship between `VEHICLES` and `DRIVERS`[cite: 7].
5. `TELEMETRY_READINGS` — High-frequency OBD-II sensor stream (`reading_id`, `device_id`, `trip_id`, `recorded_at`, `odometer_km`, `engine_temp_c`, `engine_rpm`, `oil_pressure_psi`, `coolant_temp_c`, `fuel_level_pct`, `fuel_consumption_lph`).
6. `SAFETY_AND_FAULT_ALERTS` — Threshold violations detected from telemetry readings (`alert_id`, `reading_id`, `vehicle_id`, `alert_category`, `severity_level`, `is_resolved`, `created_at`).
7. `MAINTENANCE_ORDERS` — Workshop repair orders generated by critical alerts (`order_id`, `vehicle_id`, `alert_id`, `component_type`, `scheduled_date`, `completed_date`, `repair_cost`, `order_status`) plus `SYSTEM_AUDIT_LOG` for trigger security auditing.

 2. Normalization Progression (`UNF → 1NF → 2NF → 3NF`)

 3. Raw-to-3NF Field Mapping & Phase IV Cleaning Checklist

| Raw CSV Column | Target 3NF Table | Target Column | Action / Conversion Needed in Phase IV |
|---|---|---|---|
| `vehicle_id` | `VEHICLES` (and FK in `TELEMATICS_DEVICES`, `TRIPS`, `SAFETY_AND_FAULT_ALERTS`, `MAINTENANCE_ORDERS`) | `vehicle_id` | `UPPER(TRIM(vehicle_id))`; deduplicate 50 distinct IDs (`VEH0000`–`VEH0049`) into `VEHICLES` first[cite: 7]. |
| `brand` | `VEHICLES` | `brand` | `INITCAP(TRIM(brand))`; stored once per vehicle in `VEHICLES` (10 distinct brands)[cite: 7]. |
| `timestamp` | `TELEMETRY_READINGS` | `recorded_at` | Convert text string (`YYYY-MM-DD HH:MM:SS`) to Oracle `TIMESTAMP` via `TO_TIMESTAMP()`[cite: 7]. |
| `odometer_reading` | `TELEMETRY_READINGS` & `VEHICLES` | `odometer_km` / `current_odometer` | Round 6-decimal float to `NUMBER(10,2)` via `ROUND(..., 2)`[cite: 7]. |
| `engine_temp_c` | `TELEMETRY_READINGS` | `engine_temp_c` | Round to `NUMBER(5,2)`; trigger `ENGINE_OVERHEAT` alert when `> 105.0`[cite: 7]. |
| `engine_rpm` | `TELEMETRY_READINGS` | `engine_rpm` | Round float RPM (`2212.155243`) to integer `NUMBER(5,0)` via `ROUND(..., 0)`[cite: 7]. |
| `oil_pressure_psi` | `TELEMETRY_READINGS` | `oil_pressure_psi` | Round to `NUMBER(5,2)`; trigger `LOW_OIL_PRESSURE` alert when `< 20.0`[cite: 7]. |
| `coolant_temp_c` | `TELEMETRY_READINGS` | `coolant_temp_c` | Round to `NUMBER(5,2)`; trigger `COOLANT_HIGH` alert when `> 98.0`[cite: 7]. |
| `fuel_level_percent` | `TELEMETRY_READINGS` | `fuel_level_pct` | Round to `NUMBER(5,2)`; trigger `LOW_FUEL` warning when `< 10.0`[cite: 7]. |
| `fuel_consumption_lph` | `TELEMETRY_READINGS` | `fuel_consumption_lph` | Round to `NUMBER(5,2)`; flag zero-consumption coasting rows (`= 0` while `engine_rpm >= 700`)[cite: 7]. |
